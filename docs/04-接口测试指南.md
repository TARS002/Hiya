# 没有前端时，怎么测这个服务端？

> **结论先说**：浏览器地址栏测不了——它只能发 GET 请求，而登录是 POST；而且服务器只有接口路径，
> 访问 `http://localhost:8080/` 会返回 404（这是正常的，不是出错）。
> 下面五种方式，任选一种即可，推荐顺序：① 测试页 → ② PowerShell → ③ REST Client。

---

## 第 0 步：先把服务端启动起来

任选一种（在项目根目录执行）：

```powershell
# 方式 A：Maven Wrapper（你自己电脑上正常可用）
.\\mvnw.cmd spring-boot:run

# 方式 B：直接用我下载到 .tools 里的 Maven
.tools\\apache-maven-3.9.16\\bin\\mvn.cmd spring-boot:run
```

或者在 VS Code 里直接运行 `HiyaServerApplication` 的 `main` 方法（最省事）。

**启动成功的标志**（控制台最后几行）：

```
Tomcat started on port 8080 (http) with context path '/'
Started HiyaServerApplication in 2.9 seconds
```

> 前提：MySQL 服务在跑，且 `hiya_db` 存在（见 `docs/03-数据库初始化.sql`）。
> 停止服务：在运行窗口按 `Ctrl + C`。

---

## 方式一：后端自带的测试页（推荐，能点着测）

服务端启动后，浏览器打开：

```
http://localhost:8080/test.html
```

这个页面在 `src/main/resources/static/test.html`，由后端直接托管，可以：

| 功能 | 对应接口 |
|---|---|
| 登录（已预填 `bababoye / bababoye`） | POST /api/login |
| 查当前用户 / 用户资料 / 在线列表 | GET /api/me、/api/info/{targetUserId}、/api/friend/online |
| 加载好友列表、发送好友请求 | GET /api/friend/list、POST /api/friend/request |
| 加载会话、点会话看记录、发消息 | GET /api/chat/list、/api/chat/{id}/messages、POST 消息 |
| WebSocket 连接 / 心跳 / 查看推送日志 | ws://localhost:8080/ws?userId= |

**测实时推送的方法**：把这个页面在**两个浏览器窗口**各开一个（或一个正常窗口 + 一个无痕窗口），
分别登录**不同的账号**（例如 `bababoye/bababoye` 和 `Mambo/Mambo`），
在其中一个里发消息，另一个窗口的「WebSocket 日志」会立刻出现 `BROADCAST_MESSAGE` 推送。

> 这个页面只是联调工具，正式前端是另一个工作区的 Vue3 项目，将来可以删掉。

## 方式二：PowerShell（不用装任何东西）

在 PowerShell 里复制粘贴即可（注意：中文乱码不影响结果，是控制台编码问题）：

```powershell
# 1) 登录，拿到 userId
$login = Invoke-RestMethod -Uri "http://localhost:8080/api/login" -Method Post `
         -ContentType "application/json" -Body '{"userName":"bababoye","password":"bababoye"}'
$login.data
$uid = $login.data.userId

# 2) 之后的请求都在 URL 上带 ?userId=（不是请求头）
Invoke-RestMethod -Uri "http://localhost:8080/api/me?userId=$uid"
Invoke-RestMethod -Uri "http://localhost:8080/api/friend/list?userId=$uid"
Invoke-RestMethod -Uri "http://localhost:8080/api/chat/list?userId=$uid"
Invoke-RestMethod -Uri "http://localhost:8080/api/chat/1/messages"

# 3) 发一条消息（会自动通过 WebSocket 广播给会话内在线的成员）
Invoke-RestMethod -Uri "http://localhost:8080/api/chat/1/messages?userId=$uid" -Method Post `
  -ContentType "application/json; charset=utf-8" -Body '{"content":"hello from powershell"}'
```

**看响应里的 `code`**：200 成功，400 参数错误，1002 用户名或密码错误等（见 docs/02 第 4.4 节）。

> 想完整跑一遍（含 WebSocket 推送验证）：`.tools\\e2e-test.ps1`（这是我写的自动化测试脚本，可直接运行）。

## 方式三：VS Code + REST Client 插件（在编辑器里测，不切窗口）

1. VS Code 装扩展 **REST Client**（作者 Huachao Mao）
2. 打开项目根目录的 `api-test.http`
3. 每个请求上方会出现 `Send Request`，点一下就能发，响应显示在右侧

这种方式把"请求 + 结果"都留在编辑器里，写文档/调试都方便。

## 方式四：curl（命令行，Windows 自带）

```powershell
# 登录
curl.exe -X POST http://localhost:8080/api/login -H "Content-Type: application/json" -d "{\"userName\":\"bababoye\",\"password\":\"bababoye\"}"

# 带身份标识查好友列表
curl.exe http://localhost:8080/api/friend/list -H "?userId=1"
```

> 注意：PowerShell 里用 curl 传 JSON 的引号很容易被吃掉，建议改用上面的 `Invoke-RestMethod`
> 或把 JSON 存成文件再 `-d "@body.json"`。

## 方式五：图形化工具（Postman / Apifox / Insomnia）

适合接口多、要管理变量的场景：

1. 新建请求：`POST http://localhost:8080/api/login`，Body 选 raw + JSON
2. 在环境变量里存 `userId`，每个请求的 URL 上带 `?userId={{userId}}`

Apifox 还支持 WebSocket 调试：新建 WebSocket 请求，地址 `ws://localhost:8080/ws?userId=1`。

## 常见问题

| 现象 | 原因 / 解决 |
|---|---|
| `localhost:8080` 打开是 404 | 现在不会了——`/` 是首页。若仍 404，说明服务端没启动或跑的是旧版本 |
| 完全连不上（无法访问此网站） | 服务端没启动，或端口被占用；看启动窗口有没有报错 |
| `{"code":400,"message":"缺少参数: userId"}` | 除 `/`、`/api/register`、`/api/login` 外，接口的 URL 都要带 `?userId=` |
| 请求返回 HTTP 200 但 `code` 不是 200 | **正常**：业务错误走统一响应体（如 1002 密码错），判断成败要看 `code` |
| WebSocket 连上就断 | 检查 `userId` 参数是否数字；或前端来源不在允许列表（见 `WebSocketConfig`） |
| 启动报数据库连接失败 | MySQL 没启动，或 `application.properties` 里的账号密码不对 |
| 中文显示成 `æä½æå` | 控制台编码问题，不影响数据；浏览器里显示正常 |
| **用 PowerShell 发中文变成 `?????`** | `Invoke-RestMethod` 默认不按 UTF-8 编码请求体，必须写 `-ContentType "application/json; charset=utf-8"`（见下面"方式二"示例） |

## 附：这个服务端"最小可用链路"自测清单

```
===== 板块1 注册登录 =====
[ ]  1. GET  /                        → 首页 + 接口清单
[ ]  2. POST /api/register            → 返回新 userId
[ ]  3. POST /api/login               → 返回 userId
[ ]  4. GET  /api/me?userId=1   → 返回用户信息（无 password 字段）
[ ]  5. GET  /api/me/info             → 账号 + 资料
[ ]  6. PUT  /api/me {"nickName":...} → 修改资料成功
[ ]  7. PUT  /api/me/password         → 改密码成功；旧密码再登录应失败(1002)
[ ]  8. GET  /api/info/2              → 查别人的资料
===== 板块2 聊天室 =====
[ ]  9. POST /api/chat/room {"chatTitle":"测试群"} → 返回新 chatId(type=2)
[ ] 10. GET  /api/chat/{id}/members   → 创建者自动是成员
[ ] 11. POST /api/chat/{id}/join      → 加群成功；重复加返回 409
[ ] 12. POST /api/chat/{id}/leave     → 退群成功
[ ] 13. GET  /api/chat/list           → 我的会话列表
[ ] 14. GET  /api/chat/1/messages     → 历史聊天记录
[ ] 15. POST /api/chat/1/messages     → 发送成功
===== 板块3 好友 =====
[ ] 16. GET  /api/friend/list         → 好友关系
[ ] 17. GET  /api/friend/online       → 在线用户
[ ] 18. POST /api/friend/request      → 对方不在线返回 400
===== 实时通道 =====
[ ] 19. WS /ws?userId=1 连接后发 ping → 收到 {"type":"pong"}
[ ] 20. 另一个窗口登录别的账号发消息   → 本窗口 WS 收到 BROADCAST_MESSAGE
```
