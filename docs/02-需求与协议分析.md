# Hiya 旧系统需求梳理 + 新版 API 设计

> 本文基于 `legacy/` 目录下的旧版 Hiya 服务端代码整理。
> 目标：1、完整还原旧系统功能与协议；2、定义 SpringBoot 重构版的 REST + WebSocket 接口；
> 3、作为 Vue3 客户端工作区的对接契约。

---

## 1. 旧系统架构回顾（Socket 直连）

```
客户端 --Socket(每行一条JSON)--> ClientHandler.run() 读行
  --> Command.fromJson() 解析
  --> CommandDispatcher.dispatch() 按 cmd 字段路由
  --> 对应 Handler（LoginHandler / UserHandler / FriendHandler / ChatHandler / MessageHandler）
  --> DAO（JDBC 手写 SQL）--> MySQL（hiya_db）
  <-- sendResponse() / sendNotify() 原路返回 JSON
```

### 1.1 消息协议（Command JSON）

```json
{
  "requesterId": 123,        // 请求者用户ID
  "msgType": "REQUEST",      // REQUEST=客户端请求 / RESPONSE=服务器反馈 / NOTIFY=服务器主动推送
  "code": 200,               // 200成功 400失败 401未授权 404不存在 409已存在 500服务器错误
  "cmd": "SEND_MESSAGE",     // 业务指令枚举名（见 1.2）
  "data": { ... }            // 业务数据，任意 JSON
}
```

传输规则：Socket 文本流，**每条消息一行（以换行符分隔）**，JSON 序列化用 Gson。

### 1.2 指令清单（Cmd 枚举）与业务逻辑

| cmd | 归属 Handler | data 请求字段 | 业务逻辑 | 响应 |
|---|---|---|---|---|
| LOGIN | LoginHandler | {userName, password} | 查 `hiya_user`（user_name+password **且 is_deleted=0 且 is_banned=0**）；成功→写登录日志、注册在线、绑定 userId | LOGIN_SUCCESS+User / LOGIN_FAILURE |
| GET_USER_INFO | UserHandler | {targetUserId} | 查 user + user_profile 合并 | USER_INFO_RESULT+{user, profile} |
| GET_FRIEND_LIST | FriendHandler | （无） | 查 `hiya_friend` 未删除记录 | FRIEND_LIST_RESULT+List\<Friend\> |
| ADD_FRIEND_REQUEST | FriendHandler | {friendId} | 不能加自己；已是好友→409；**目标在线才通知**（不落库） | NOTIFY 目标 FRIEND_REQUEST_NOTIFY+{requesterId, requesterName} |
| ADD_FRIEND_ACCEPT | FriendHandler | {requesterId} | 双向插入好友关系 | NOTIFY 请求方 ADD_FRIEND_RESULT |
| ADD_FRIEND_REJECT | FriendHandler | {requesterId} | 不落库 | NOTIFY 请求方 ADD_FRIEND_RESULT+{success:"false"} |
| DELETE_FRIEND | FriendHandler | {friendId} | 双向逻辑删除（is_deleted=1） | DELETE_FRIEND_RESULT |
| GET_CHAT_LIST | ChatHandler | （无） | member 表查 chatIds → chat 详情 | CHAT_LIST_RESULT+List\<Chat\> |
| CREATE_PRIVATE_CHAT | ChatHandler | {friendId} | 已有私聊直接返回；否则建 chat(type=1)+加两个成员 | PRIVATE_CHAT_RESULT+Chat |
| GET_CHAT_MEMBERS | ChatHandler | {chatId} | member 表查 userIds → 用户信息 | CHAT_MEMBERS_RESULT+List\<User\> |
| SEND_MESSAGE | MessageHandler | {chatId, msgType, content} | 落库 → 发送者收 SEND_MESSAGE_RESULT；向聊天室**所有在线成员**广播 | 发送者 RESPONSE；成员 NOTIFY BROADCAST_MESSAGE+Message |
| GET_CHAT_MESSAGES | MessageHandler | {chatId} | 查未撤回消息，send_time 升序 | CHAT_MESSAGES_RESULT+List\<Message\> |

**关键事实**：
- 旧系统**没有注册功能**（新系统补上，登录前置）；
- 密码**明文存储**（登录 SQL 直接比较 password 字段）；
- 好友请求**不持久化**，目标离线则请求丢失（旧系统局限，新版沿用并注明改进方向）；
- 消息广播**包含发送者自己**（旧代码把排除逻辑注释掉了）；
- 群聊字段存在（type=2、role 等），但旧系统**只有私聊创建指令**，无群聊创建/加入指令。

### 1.3 在线管理

- `HiyaServer.onlineClients`：`ConcurrentHashMap<Long userId, ClientHandler>`；
- 登录成功才注册在线；连接断开（cleanup）移除；
- **无主动下线指令**（代码注释承认是设计失误）。

## 2. 数据库表结构（从模型类 + DAO SQL 还原）

> 旧库名 `hiya_db`，连接信息 `root/123456@localhost:3306`。
> 新版 JPA 实体与下表一一对应（ddl-auto=update 可自动建表/加列）。

### hiya_user（用户主表）
| 列 | 类型(推断) | 说明 |
|---|---|---|
| user_id | BIGINT PK 自增 | 用户ID |
| user_name | VARCHAR 唯一 | 用户名，登录用 |
| password | VARCHAR | 密码（旧系统明文） |
| is_banned | INT | 0未封禁 1已封禁 |
| unban_time | VARCHAR/DATETIME | 解封时间 |
| create_time | VARCHAR/DATETIME | 创建时间 |
| update_time | VARCHAR/DATETIME | 更新时间 |
| is_deleted | INT | 0未删除 1已删除 |

### hiya_user_profile（用户资料表）
| 列 | 说明 |
|---|---|
| user_profile_id | PK 自增 |
| user_id | 关联用户 |
| nick_name | Hiya 昵称 |
| avatar_url | 头像 URL |
| signature | 个性签名 |
| gender | 0不便透露 1男 2女 |

### hiya_user_login_log（登录日志表）
| 列 | 说明 |
|---|---|
| id | PK 自增（推断） |
| user_id | 登录用户 |
| login_time | 登录时间（推断，默认 CURRENT_TIMESTAMP） |

### hiya_chat（聊天会话表）
| 列 | 说明 |
|---|---|
| chat_id | PK 自增 |
| type | 1私聊 2群聊 |

### hiya_chat_member（会话成员表）
| 列 | 说明 |
|---|---|

| chat_id | 会话ID（与 user_id 联合唯一） |
| user_id | 成员ID |

### hiya_friend（好友关系表，双向两行）
| 列 | 说明 |

### hiya_message（消息表）
| 列 | 说明 |
|---|---|

| sender_id | 发送者 |
| chat_id | 所属会话 |
| msg_type | 1文本 2图片 3文件 4语音 5系统 |
| content | 内容 |
| send_time | 发送时间 |
| is_deleted | 0正常 1已撤回 |

## 3. 新版 B-S 架构映射

| 旧（Socket 单通道） | 新（B-S 双通道） | 说明 |
|---|---|---|
| 请求-响应类指令（LOGIN、GET_*、CREATE、DELETE、SEND） | **REST API**（见第 4 节） | HTTP 请求/响应，URL 带 userId 参数标识身份 |
| NOTIFY 推送（好友请求通知、消息广播） | **WebSocket**（/ws） | 服务器主动推送，?userId= 标识身份 |
| onlineClients（ConcurrentHashMap） | SessionManager（ConcurrentHashMap\<userId, WebSocketSession\>） | 在线管理 |
| Command JSON（每行一条） | REST：统一 Result{code,message,data}；WS：{type, data} | 协议简化 |
| Gson | Jackson 3（SpringBoot 默认） | 框架自带 |

### 用户身份怎么传（简化设计，无认证）

| 场景 | 方式 | 示例 |
|---|---|---|
| 登录 / 注册 | 不需要身份 | `POST /api/login` |
| 其他 REST 接口 | URL 参数 `userId` | 例：`GET /api/me?userId=1` |
| WebSocket 连接 | URL 参数 `userId` | `ws://localhost:8080/ws?userId=1` |

> 服务器只做"标识"不做"校验"：不带 `userId` 时返回 400（缺参数），
> 带了就按该用户处理（不验证你是否真的是他）。

### WebSocket 推送协议（服务器 → 客户端）

```json
{"type":"pong"}                                              // 心跳应答
{"type":"FRIEND_REQUEST_NOTIFY","data":{"requesterId":1,"requesterName":"hiya"}}
{"type":"ADD_FRIEND_RESULT","data":{"message":"对方已同意你的好友请求","success":true}}
{"type":"BROADCAST_MESSAGE","data":{"id":1,"senderId":1,"chatId":2,"msgType":1,"content":"你好","sendTime":"...","isDeleted":0}}
```

客户端 → 服务器：`{"type":"ping"}`（心跳）。业务上行全部走 REST。

## 4. 五个入口（Controller）与 REST API 一览（Vue3 前端对接契约）

> 统一响应格式：`{"code":200,"message":"操作成功","data":...}`；失败时 data 为 null。
> 除 `/`、`/api/register`、`/api/login` 外，所有接口都需要在 URL 上带 `userId` 参数，例如 `?userId=1`。
>
> **⚠️ 前端必须注意**：业务错误返回的是 **HTTP 200 + body 里的 code**（如 1002 密码错误、409 已是好友），
> 所以判断成败要**看 `code` 字段**，不能只看 HTTP 状态码；只有"缺少参数"（比如忘写 ?userId=）才是真正的 HTTP 400。

| 入口 | Controller | 说明 |
|---|---|---|
| `GET /` | HomeController | 首页：服务状态 + 接口清单（无需身份） |
| `POST /api/register` | RegisterController | 注册（无需身份） |
| `POST /api/login`、`/api/me`、`/api/info/{id}` | LoginController | 登录与用户信息 |
| `/api/chat/**` | ChatController | 聊天 |
| `/api/friend/**` | FriendController | 好友 |
| `WS /ws?userId=` | ChatWebSocketHandler | 实时推送通道 |

### 4.1 板块1：注册登录 + 查询/修改自己的数据

| 方法 | 路径 | 请求体 | 说明 |
|---|---|---|---|
| GET | / | — | 首页：服务状态 + 全部接口清单（无需身份） |
| POST | /api/register | {userName, password} | 注册（用户名唯一校验、字段长度校验；无需身份头） |
| POST | /api/login | {userName, password} | 登录，返回 {userId, userName} 和一条登录日志（唯一不需要 userId 的接口之一） |
| GET | /api/me | — | 查询我自己的账号信息 |
| GET | /api/me/info | — | 查询我自己的账号 + 资料 |
| PUT | /api/me | {nickName?, avatarUrl?, signature?, gender?, birthday?} | **修改我自己的资料**（字段可选，只传要改的；没有资料会自动创建） |
| PUT | /api/me/password | {oldPassword, newPassword} | **修改我自己的密码**（需原密码校验） |
| GET | /api/info/{targetUserId} | — | 查询**别人**的账号 + 资料（对应 GET_USER_INFO） |

登录请求与响应示例：

```
POST /api/login
{"userName":"bababoye","password":"bababoye"}

→ {"code":200,"message":"操作成功","data":{"userId":1,"userName":"bababoye"}}
```

修改资料示例：

```
PUT /api/me
?userId=1
{"nickName":"新昵称","signature":"今天也要写代码","gender":1}

→ {"code":200,"data":{"user":{...},"profile":{"nickName":"新昵称",...}}}
```

### 4.2 板块3：好友（FriendController）

| 方法 | 路径 | 请求体 | 说明 |
|---|---|---|---|
| GET | /api/friend/list | — | 好友列表（对应 GET_FRIEND_LIST） |
| GET | /api/friend/online | — | 在线用户 ID 列表（前端用来标"在线"） |
| POST | /api/friend/request | {friendId} | 申请加好友（服务器通过 WebSocket 通知对方；对方不在线就收不到） |
| POST | /api/friend/accept | {requesterId} | 同意好友申请（对应 ADD_FRIEND_ACCEPT） |
| POST | /api/friend/reject | {requesterId} | 拒绝好友申请（对应 ADD_FRIEND_REJECT） |
| DELETE | /api/friend/{friendId} | — | 删除好友（对应 DELETE_FRIEND） |

### 4.3 板块2：聊天室（ChatController）—— 三大任务

**① 管理聊天室**

| 方法 | 路径 | 请求体 | 说明 |
|---|---|---|---|
| GET | /api/chat/list | — | 我加入的所有会话（私聊 + 群聊） |
| POST | /api/chat/room | {chatTitle} | **创建群聊**（创建者自动成为群主 role=2） |
| POST | /api/chat/private | {friendId} | 创建/获取私聊会话（对应 CREATE_PRIVATE_CHAT） |

**② 管理聊天室里的人员**

| 方法 | 路径 | 请求体 | 说明 |
|---|---|---|---|
| GET | /api/chat/{chatId}/members | — | 会话成员（对应 GET_CHAT_MEMBERS） |
| POST | /api/chat/{chatId}/join | — | **加入群聊**（插一行成员记录） |
| POST | /api/chat/{chatId}/leave | — | **退出群聊**（删一行成员记录） |

**③ 管理聊天室里的消息**

| 方法 | 路径 | 请求体 | 说明 |
|---|---|---|---|
| GET | /api/chat/{chatId}/messages | — | 聊天记录（对应 GET_CHAT_MESSAGES） |
| POST | /api/chat/{chatId}/messages | {msgType?, content} | 发送消息（落库 + WebSocket 广播给会话内在线成员） |

### 4.4 状态码约定

| code | 含义 | 说明 |
|---|---|---|
| 200 | 操作成功 | |
| 400 | 请求参数错误 / 操作失败 | 如"原密码错误""缺少参数: userId" |
| 404 | 资源不存在 | 如"聊天会话不存在" |
| 409 | 资源已存在 | 保留未用 |
| 1001 | 用户名已被注册 | 业务码 |
| 1002 | 用户名或密码错误 | 业务码 |
| 1003 | 用户不存在 | 业务码 |
| 500 | 服务器内部错误 | |

> 注：原设计有 401（未登录/登录过期），取消 JWT 认证后已不再使用。
